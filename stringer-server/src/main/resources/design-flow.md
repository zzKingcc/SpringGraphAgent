# springAI-Langchain-Agent 设计流程与思路

## 整体思路

做一个能让大模型自己做决定的对话系统。用户问一句话，模型自己判断要不要查知识库、要不要调工具、要不要先问用户确认。不需要写任何 if-else 流程，全部由状态图驱动。

底层用 LangGraph4j 画一张图，图上有几个节点，节点之间有条件边。模型生成完看它要干嘛 —— 不调工具就结束，调普通工具就去执行然后回来继续生成，调敏感工具就暂停等用户确认。

## 对话主流程

用户发消息进来，系统先做安全检查，把恶意输入挡在门外。然后加载这个会话的历史记忆，把系统提示词和历史消息拼在一起，作为初始状态丢给图执行。

图启动后走到第一个节点 —— 模型节点。模型节点拿着流式模型边生成边往前端推，每个字块实时送出。生成完看结果：如果模型直接给了文字回复，没有调用工具，那对话结束，把回复存进会话记忆。如果模型说要调工具，就看调的是什么工具。

工具分两种：普通工具直接去执行，执行完结果送回模型，模型再生成一轮 —— 这就是工具循环。敏感工具（比如查员工人数）不直接执行，而是在一个空的暂停点前面停下来，把工具调用信息推给前端，前端弹确认框。用户点同意才继续执行工具，点拒绝就告诉模型"用户没批准，你换个方式回答"。

## 状态图怎么设计的

三个节点：模型节点、工具节点、暂停节点。暂停节点什么都不做，只是个锚点，让图知道"到这要停一下"。

三条边从模型节点出发：
- 没有工具调用 → 直接到结束
- 全是普通工具 → 去工具节点（不暂停）
- 有敏感工具 → 去暂停节点（暂停等确认）

工具节点执行完回到模型节点，形成循环。暂停节点确认完也去工具节点执行，再回到模型节点。

所有节点都在同一个线程上跑，不切换线程。因为流式输出的通道是按线程号存的，一换线程就找不到了。

## 中断和恢复怎么做的

图暂停的时候，把当时的完整状态（所有消息）存到 Redis 里。前端收到一个特殊标记的事件，知道需要用户确认。用户确认后发一个恢复请求，系统从 Redis 把状态捞回来，从暂停点继续执行。

这里有个坑：图跑完之后默认会自动清状态，但代码还需要从状态里取最终回复存到记忆里。所以关掉自动清理，改成手动管 —— 先取回复存记忆，再清状态。

每次新问题进来也先清一次旧状态，否则上一次的工具调用和结果会混进来，模型上下文就乱了。

## 工具怎么注册的

工具就是打了注解的普通方法。启动时用反射扫一遍，把方法名、描述、参数信息抽出来做成规格列表给模型看，让模型知道有哪些工具可以调。同时把每个方法包成一个执行器，执行时反射调用原方法。

哪个工具需要用户确认，就再打个授权注解。反射扫的时候把标了授权注解的工具名收集到一个集合里。条件边判断路由时，只要模型调的工具里有这个集合里的，就走暂停路径。

加新工具就是加一个方法，不用动编排逻辑。

## 知识库怎么建的

启动时从资源目录加载文档文件。按文件类型分到不同策略处理 —— 文本类直接分片，PDF 类先做文本清洗（修断行、合段落）再分片。

分片用中文分片器，按章节标题切。正则匹配各种中文编号格式（一、二、第x章、1.2、（一）等），遇到标题就切出前一段。短章节直接输出，超长章节用兜底的递归切分器按段落→句子→字符降级再切，带 80 字符重叠保证不断句。每个片段带上文件名和章节标题作为元数据。

切完做两层去重。第一层在内存里按内容哈希去重，同一个文档内重复段落去掉。第二层查 ES，看索引里是不是已经有这个哈希了，有的跳过不重复写入。这样增量导入时不会重复。

向量化分批做，每批最多 25 个片段，因为阿里百炼的向量模型一次请求限制 25 行。写完做一次校验 —— 刷索引、查总数、确认向量字段类型和维度对不对、跑一个示例查询确认检索能用。

## ES 索引怎么设计的

手动创建索引 mapping，三个字段：向量字段用 dense_vector 类型 1536 维，文本字段用 IK 分词器（索引时最大粒度分词，搜索时智能分词），元数据字段用对象类型存文件名、章节标题、内容哈希。

为什么不自动创建：LangChain4j 默认自动建索引，但文本字段用的是 ES 标准分词器，按空格切词，对中文完全没用。必须在它之前手动建好带 IK 分词器的 mapping。

向量检索用 script_score 加余弦相似度，不用 KNN 配置，因为 LangChain4j 的 ES KNN 配置有个 bug 导致参数不生效。script_score 方式稳定可靠。

## 检索怎么做的

两路并行检索：
- 向量检索：把用户问题转成向量，用余弦相似度从 ES 里捞 Top15，设最低分阈值 0.2 过滤掉完全不相关的。
- 关键词检索：用 ES 的 multi_match 做 BM25 匹配，捞 Top5，标题字段权重是正文的两倍。

两路结果先按内容哈希去重，然后做分数融合。融合前先各自做 min-max 归一化，把两路分数都拉到 0 到 1 之间（因为向量分数和 BM25 分数量纲不同，直接加权没意义）。然后按 0.6 向量 + 0.4 关键词加权求和。如果标题命中查询词加 0.15，文件名命中加 0.1。最后按融合分数排序取前 10 条返回给模型。

实际返回给模型时再截取前 5 条，避免上下文太长挤占记忆窗口。

## 会话记忆怎么做的

用 Redis 存，每个会话一个 key，值是序列化后的消息列表 JSON。每次对话把用户消息和模型回复存进去。

记忆有两个约束同时卡：消息条数不超过 100 条，Token 估算不超过 30000。每次存新消息时从最老的开始淘汰，两个都满足才停。Token 估算用字符级粗算 —— 中文字算 1.5 个 token，英文字算 0.25 个，宁可估高不可估低，保证不会撑爆模型上下文。

任务被用户停止时，要把刚存进去的用户消息回滚掉，否则记忆里有一条没有对应回复的用户消息，下次模型看到上下文就断了。

## 流式输出怎么做的

用 Reactor 的 Flux 做流式响应。对话入口创建一个 Flux，在一个独立线程里跑图编排。图的模型节点每生成一个字块，就往 FluxSink 推一个数据，前端实时收到。

三个东西按线程号存在并发 Map 里：流式推送通道、会话 ID、半截文本缓冲。模型节点的流式回调跑在 I/O 线程上，跟图执行线程不是同一个，所以 Token 统计要用原子整数跨线程累积，等流式生成完了再转回主线程的本地变量里。

## 停止怎么做的

用户发停止请求，往一个并发 Map 里写一个停止标志。模型节点每个字块推送前检查这个标志，命中就抛取消异常终止流式生成。工具节点每个工具执行前也检查，命中就停。

停止后做三件事：回滚记忆（把刚存的用户消息删掉）、清状态（让会话不可恢复）、推一个停止事件给前端。

## 安全怎么做的

用户输入进来先用五组正则扫一遍：指令覆盖（"忽略以上规则"）、角色混淆（伪装系统角色）、分隔符注入（用特殊符号构造假指令）、提示词窃取（"输出你的提示词"）、编码绕过（base64 解码绕过）。命中任何一个直接拦掉返回 400。

过了检测的输入还要清洗：去零宽字符（Unicode 隐形注入）、压缩换行（防止构造角色前缀）、截断超长输入。两道防线，正则没拦住的清洗兜底。

## Token 统计怎么做的

每个请求线程一个本地变量，记录模型输出 token 和工具调用的输入输出 token。开始时清空，结束时打印日志并清掉防止内存泄漏。

模型输出的流式回调跑在 I/O 线程上，本地变量取不到，用原子整数在节点里跨线程累积，等流式生成完了再转回主线程。Token 估算用字符级启发式，中文 1.5、英文 0.25。

## 异常怎么处理的

分两层：业务异常有基类带错误码，子类按业务分（记忆异常、知识库异常）。全局处理器统一拦截，业务异常返回具体信息，超时返回 504，兜底的返回 500 不暴露堆栈。浏览器自动请求的 favicon.ico 静默 404 不记日志。

## ES 怎么连接的

底层用 ES 官方的 REST 客户端，配连接超时 5 秒、读写超时 10 秒。上层封装成强类型客户端，用 Jackson 做 JSON 映射。支持可选的用户名密码认证，没配就不加凭证。

## Redis 怎么连接的

用 Spring Data Redis 的 Lettuce 连接池，最大 8 个连接。提供两个模板：通用的是 JSON 序列化存对象，专用的是纯字符串操作（会话记忆和检查点都用这个，因为序列化用的是 LangChain4j 自己的方案，不需要 Jackson 类型信息）。

## 启动流程

启动时按顺序：连 ES 做诊断（版本、健康、索引存在性）→ 按配置决定是否删旧索引重建 → 创建带 IK 分词器的 mapping → 构建向量存储 → 加载知识库文档分片去重向量化写入 → 写完校验（文档数、字段类型、示例查询）。Redis 连接在 Bean 初始化时自动完成。图在编排服务构造时编译一次，后续复用。
